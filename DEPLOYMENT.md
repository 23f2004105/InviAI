# Deploying InviAI (free tier)

| Part | Service | Free tier notes |
|---|---|---|
| Database | [Neon](https://neon.tech) Postgres | 0.5 GB storage; compute sleeps when idle and wakes in about a second |
| Backend | [Render](https://render.com) web service | 512 MB RAM; sleeps after ~15 min idle, first request then takes ~30-60 s |
| Frontend | [Vercel](https://vercel.com) | Hobby plan |

The repo must be on GitHub (Render and Vercel deploy from it). Do the steps in this order, because each one needs a URL from the one before.

## 1. Database: Neon

1. Create a project (region: Singapore or Mumbai, closest to Indian users).
2. On the dashboard, copy the connection string with **Connection pooling turned off** (the direct host, without `-pooler`). It ends in `?sslmode=require`.
3. Keep it for step 2. Tables are created by the backend on first start.

## 2. Backend: Render

1. Render dashboard → **New → Blueprint** → choose the repo. It reads `render.yaml`.
2. When asked, fill in:
   - `DATABASE_URL`: the Neon string from step 1
   - `CORS_ORIGINS`: leave as `http://localhost:3000` for now (updated in step 4)
   - `GEMINI_API_KEY`: your key from https://aistudio.google.com (optional)
   - `JWT_SECRET_KEY` is generated by Render automatically.
3. Deploy. When it is live, open `https://<your-service>.onrender.com/health` and check `"database": "healthy"`.

## 3. Frontend: Vercel

1. Vercel → **Add New → Project** → import the repo.
2. **Root Directory**: `InviAI-Frontend`. Framework preset: Next.js.
3. Environment variables (Production):
   - `NEXT_PUBLIC_API_URL` = `https://<your-service>.onrender.com`
   - `BACKEND_URL` = `https://<your-service>.onrender.com`
4. Deploy and note the URL, e.g. `https://inviai.vercel.app`.

## 4. Connect them

In Render → your service → **Environment**, set `CORS_ORIGINS` to the Vercel URL (comma-separate several, e.g. a custom domain too). Render redeploys automatically.

## 5. Check

- Open the Vercel URL, register an account, create a portfolio, add a stock (e.g. `RELIANCE`).
- Optional: load the demo account: `$env:INVIAI_API_URL="https://<your-service>.onrender.com"; python backend/seed_demo.py`

## Notes

- **Cold starts:** the free Render service sleeps. A free uptime pinger (e.g. UptimeRobot hitting `/health` every 10 min) keeps it awake during a demo.
- **Secrets:** never commit `.env` files. Rotate `JWT_SECRET_KEY` in Render to log everyone out.
- **Schema changes:** add an Alembic migration (see README). It is applied automatically on the next deploy.
- **Single worker:** rate limits and the price cache are in memory, so keep one uvicorn worker. Moving to several workers would need Redis for both.
